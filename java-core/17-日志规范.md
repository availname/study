# 17 · 日志规范：写给"凌晨 3 点的你"

生产排查 90% 靠日志——[13 篇 Linux 排查](13-运维部署实战/02-Linux排查命令速查.md) 的 grep 三剑客再熟练，**日志本身没写好也是白搭**。日志是"没系统学过但天天在写"的又一典型（上一个是[接口规范](16-接口设计规范.md)），本篇把 mq-mall/community 里已经"写对了一半"的日志补全成体系。

## 一、门面与实现：slf4j + logback，一行都不能错

```
✅ Spring Boot 默认：slf4j 门面 + logback 实现（@Slf4j 注解声明 logger）
❌ System.out.println —— 无级别（生产关不掉）/无时间线程/同步阻塞主流程/不落文件
❌ 直接 import log4j/Logback 的原生 API —— 锁死实现，换不了
❌ 两套日志框架共存（桥接冲突，日志"消失"的经典原因）
```

**为什么必须有门面**：日志是横切关注点，业务代码面向 `Logger` 接口编程，实现可替换——IoC 思想（[04-Spring](04-Spring核心原理/README.md)）在日志领域的翻版。

## 二、一条合格的日志长什么样

```
2026-11-09 15:30:02.318  INFO  [order-pool-3] c.e.m.OrderService [traceId=8f3a2b] [下单成功] orderNo=O2026... userId=9 skuId=1 count=2
└─ 时间(毫秒)          └级别  └线程名      └缩略类名    └全链路ID                └业务键值对
```

**六要素缺一不可**：时间（毫秒级）、级别、线程名（排查线程池问题全靠它）、traceId（全链路串联，见第五节）、发生位置（类名）、**结构化的业务键值**。

❌ `"用户下单失败"` —— 没有订单号、没有用户、没有原因，等于没打
✅ `"下单失败 orderNo={} userId={} skuId={} reason={}"` —— 键值齐全，grep 一把梭

## 三、级别：四个级别四种责任

| 级别 | 语义 | 责任边界 | 例子（mq-mall 真实日志） |
|------|------|---------|------------------------|
| ERROR | **需要人介入**，要配告警 | 打了 ERROR 就必须有人跟进 | `[发送失败-待补偿] messageId={} err={}` |
| WARN | 可自动恢复，但要关注 | 累计多了升级排查 | 库存漂移自动归还、重试第 2 次 |
| INFO | 关键业务动作/状态流转 | 走读业务链路的"故事线" | `[下单成功]`/`[支付成功]`/`[补偿] 重发` |
| DEBUG | 排查细节 | 生产默认关，需要时动态开 | Lua 脚本入参、SQL 参数 |

**两条铁律**：①ERROR 必须带**上下文**（参数、入参、异常堆栈）——凌晨 3 点你只有这一行；②**跳过路径也要打日志**（mq-mall 踩坑实录坑二的教训：幂等跳过静默 return，数据"无声消失"无从排查——跳过 = INFO，这是可观测性问题）。

## 四、占位符与异常：两处最高频错误

```java
// ❌ 字符串拼接：即使日志级别被关，拼接照样执行（白耗 CPU + 产生垃圾对象）
log.debug("消费消息 " + messageId + " payload: " + bigPayload);

// ✅ 占位符：级别关闭时连参数装箱都不发生
log.debug("消费消息 {} payload: {}", messageId, bigPayload);

// ❌ e.getMessage() —— 只留"唯一索引冲突"一句话，堆栈全丢，等于没打
log.error("支付失败 orderNo={} err={}", orderNo, e.getMessage());

// ✅ 异常作最后一个参数，logback 打完整堆栈（含 Caused by 链）
log.error("支付失败 orderNo={}", orderNo, e);

// ❌ catch 后既 log.error 又 throw —— 上游全局处理器再打一遍，同一错误日志翻倍
// ✅ 要么 log 完就地处理，要么 log.warn 后 throw（不打 ERROR）
```

**配全局异常处理器**（[异常篇](00-Java语言基石/04-异常体系与最佳实践.md)的 BizException + `@RestControllerAdvice`）：业务代码里**零 try-catch**，异常统一冒泡到全局处理器打 ERROR + 返回统一响应体——日志责任单一化（community 真实写法）。

## 五、traceId：跨服务串联日志的钥匙

```
用户请求 → 网关生成 traceId=8f3a2b
        → 订单服务（MDC 塞入）        日志都带 [traceId=8f3a2b]
        → MQ 消息头携带 → 库存服务     MDC 重新塞入，日志继续串联
        → 支付渠道回调 → 查单补偿      还能串回来
排查姿势：grep "8f3a2b" 各服务日志 → 一条时间线还原全链路
```

```java
// 入口拦截器：进来塞，走了清（线程复用必须清，ThreadLocal 同源问题——[并发篇](01-并发编程/README.md)）
MDC.put("traceId", Ids.nextId() + "");
try { chain.doFilter(request, response); }
finally { MDC.clear(); }

// logback pattern 里加 %X{traceId}
<property name="pattern" value="%d %-5level [%thread] %logger [%X{traceId}] %msg%n"/>
```

**MQ 场景的坑**：异步消费在新线程执行，MDC 不会自动跟过去——**traceId 要放进消息头**，消费者收到后手动 `MDC.put`。做到极致就是 [OpenTelemetry 全链路追踪](../stage6-新技术专题/04-OpenTelemetry全链路追踪.md)（自动埋点+采样+Exporter）——traceId 是它的手工版，先懂手工版才看得懂 OTel 在自动化什么。

## 六、文件滚动与生产安全

```xml
<!-- 按天 + 按大小双滚动，保留 30 天（磁盘要算账：日均 2GB × 30 = 60GB 预算） -->
<rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
    <fileNamePattern>logs/app.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
    <maxFileSize>500MB</maxFileSize>
    <maxHistory>30</maxHistory>
</rollingPolicy>
```

**三条安全红线**：

1. **敏感信息脱敏**：手机号 `138****8000`、身份证、token；❌ 整个请求体/响应体直接 toString（密码、支付参数全泄）
2. **日志即存储成本**：DEBUG 全开一天 50GB 不是玩笑——生产用 logback 动态级别（`-Dlogging.level.com.example=debug` 重启生效，或 admin 端点热调）
3. **循环里不打 INFO**：万次循环 = 万行日志刷屏，日志风暴比业务故障更能打挂磁盘 IO（[虚拟线程篇](../stage6-新技术专题/01-VirtualThreads虚拟线程.md) 的"瓶颈转移"意识：并发上去后日志 IO 会变成新瓶颈）

## 高并发实战：AsyncAppender 与指标联动

```xml
<!-- 同步 appender：业务线程亲自写磁盘，高峰期被日志 IO 拖慢 -->
<appender name="FILE" class="...">...</appender>

<!-- 异步：业务线程只入内存队列，独立线程负责刷盘 -->
<appender name="ASYNC" class="ch.qos.logback.classic.AsyncAppender">
    <queueSize>4096</queueSize>          <!-- 队列满时默认丢弃 ERROR 以下级别 -->
    <neverBlock>true</neverBlock>        <!-- 宁丢日志不堵业务 -->
    <appender-ref ref="FILE"/>
</appender>
```

**认知升级**：日志是"可丢的旁路数据"，业务是主线——这与"重要任务不进内存队列、走 MQ"（[线程池链](模拟面试追问链.md)）是同一个判据的反向应用。**ERROR 频次本身就是监控指标**（[监控告警篇](13-运维部署实战/04-监控告警与Metrics.md)：日志关键字告警是最朴素的告警手段）。

## 面试问法

**Q: 你们项目的日志规范是怎么定的？**
A: 六个方面：①slf4j 门面 + logback，禁 System.out；②日志六要素——时间/级别/线程/traceId/位置/业务键值对，杜绝"下单失败"这种无上下文日志；③级别即责任——ERROR 配告警必须人跟进、WARN 自动恢复要关注、INFO 记业务动作故事线、DEBUG 生产默认关动态开；④占位符不拼接，异常作最后参打全堆栈，全局异常处理器统一 ERROR；⑤MDC traceId 全链路串联，MQ 场景 traceId 随消息头传递；⑥文件按天+大小滚动保留 30 天，敏感信息脱敏，高并发场景 AsyncAppender 宁丢日志不堵业务。
