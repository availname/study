## 生产检查清单（代码评审时过一遍）

- [ ] 共享可变状态都有同步手段？——**最好的同步是"没有共享"**（不可变对象/局部变量/消息传递）
- [ ] 锁对象是 `private final`？没有锁 String/Integer 缓存对象？
- [ ] `tryLock` 用了？拿不到锁的分支有交代？
- [ ] `unlock` 在 finally？`ThreadLocal.remove` 在 finally？
- [ ] `InterruptedException` 被捕获后恢复中断标志了？
- [ ] 线程池手写（非 Executors）？队列有界？拒绝策略有日志/告警？
- [ ] 线程有名字（ThreadFactory）？堆栈里能认出是谁？
- [ ] JDK 21 + 虚拟线程：`synchronized` 块里没有长阻塞 IO（pinning）？
- [ ] 复合操作（check-then-act）用了原子复合方法（putIfAbsent/computeIfAbsent/CAS）？
- [ ] 双重检查锁的 instance 是 volatile？

## 一条主线串起七篇（理解记忆版）

```
线程贵（05 篇动机）→ 共享变量会乱（01/03 问题）→ 两条路解决：
  路线A 互斥（一次只有一个人改）：synchronized(02) → AQS 显式锁(06)
  路线B 无锁乐观（先改，冲突再重试）：CAS 原子类(04)
容器要并发 → ConcurrentHashMap/COW/BlockingQueue(07)
    │
    └─ 都不够用/太复杂时 → 换思路：不共享！消息传递（MQ）/不可变/虚拟线程(stage6/01)
```

**元认知**：并发问题的本质永远是三件事——**可见性、原子性、有序性**（03 篇 JMM）。所有工具都是在其中某几项上做保证。看到任何并发 bug，先问是三者中的哪一个坏了。

## 衔接虚拟线程（stage6/01）

| 平台线程世界 | 虚拟线程世界的变化 |
|-------------|-------------------|
| 线程池池化（复用贵线程） | 一个任务一个线程，**不池化** |
| 线程数=限流器 | 改用 **Semaphore/信号量**限流（线程不限流了） |
| synchronized 随便用 | ⚠ JDK21 块内阻塞 pinning，IO 场景换 ReentrantLock |
| CompletableFuture 编排 | 直接同步顺序写 + invokeAll 并行 |
| ThreadLocal 可用但小心 | 内存放大 + 跨线程丢失 → ScopedValue 方向 |

## 面试总纲（把七篇串成一次回答）

**Q: 谈谈你对 Java 并发的理解。**
A: 三层递进——
①**问题本质**（JMM）：可见性/原子性/有序性，根因是工作内存副本+指令重排；
②**两大路线**：互斥（synchronized 锁升级、AQS 显式锁）与无锁（CAS 原子类、注意 ABA/自旋）；
③**工程化**：线程池（七参数/拒绝策略/动态调参）、并发容器（CHM 的 CAS+锁桶、COW、BlockingQueue）、ThreadLocal（弱引用泄漏）、协作工具（Latch/Barrier/Semaphore）。
收敛原则：能不可变就不共享，能 CAS 就不加锁，锁就缩小粒度，IO 密集上虚拟线程，跨进程上 Redis/DB。
