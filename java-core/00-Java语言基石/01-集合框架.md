# 01 · 集合框架：ArrayList、HashMap 与选型

## 全家福一张图

```
Collection
 ├─ List（有序可重复）
 │   ├─ ArrayList  ← 数组，随机访问快      【默认选择】
 │   ├─ LinkedList ← 双向链表，两端操作快   【几乎不用，见下】
 │   └─ CopyOnWriteArrayList（并发，并发篇07）
 └─ Set（不重复）
     ├─ HashSet   ← 底层就是 HashMap（value 是哑对象）
     ├─ LinkedHashSet（保持插入序）
     └─ TreeSet（排序 = 红黑树）
Map（键值对，不属于 Collection）
 ├─ HashMap      ← 数组+链表/红黑树       【默认选择】
 ├─ LinkedHashMap（保持插入序 + LRU 淘汰姿势）
 ├─ TreeMap（按 key 排序 = 红黑树）
 └─ ConcurrentHashMap（并发，并发篇07）
```

## ArrayList vs LinkedList：面试陷阱题

| 操作 | ArrayList（数组） | LinkedList（双向链表） |
|------|------------------|----------------------|
| 随机访问 get(i) | O(1)（数组下标） | O(N)（从头遍历） |
| 尾部 add | 均摊 O(1)（扩容复制） | O(1) |
| **中间插删** | O(N)（整体移动） | O(1)（找到位置后）——但**找到位置本身 O(N)** |
| 内存 | 连续（CPU 缓存友好） | 每节点额外前后指针 |

**真相**：LinkedList 的"中间插删 O(1)"是骗人的——先要 O(N) 遍历到位置。加上数组有**CPU 缓存局部性**优势，实测 ArrayList 几乎全面胜出。**结论：默认 ArrayList；LinkedList 只在明确的"两端操作队列"场景考虑（且 BlockingQueue 更好）**。

## HashMap：面试最高频（四层递进）

### ① 底层结构（JDK8）

```
数组 + 链表 + 红黑树
   put(key, value):
     hash = (h = key.hashCode()) ^ (h >>> 16)   ← 高低 16 位异或：让高位也参与，减少碰撞
     index = hash & (table.length - 1)           ← 容量恒为 2 的幂 → 位运算代替取模
     桶空 → 直接放
     桶非空 → 链表尾插（比较 hash+equals）
              链表长度 ≥8 且数组 ≥64 → 链表转红黑树（O(N)→O(logN)）
```

### ② 扩容：2 倍 + rehash 的巧思

容量恒为 2 的幂 → 扩容 2 倍后，元素的**新位置要么在原下标，要么在原下标+旧容量**（只看 hash 那一位新增的 bit）——不需要重新计算 hash，逐个判断移动即可。

```
负载因子 0.75：size > capacity × 0.75 → 扩容 2 倍
阈值 8 转红黑树的深层原因：泊松分布下链表长度到 8 的概率约千万分之一——正常情况几乎不会转（转了说明哈希质量差或被攻击）
```

### ③ JDK7 的死循环（历史考点）

JDK7 头插法 + 并发扩容 → 链表成环 → get 死循环 CPU 100%。JDK8 改尾插解决——但**HashMap 依然线程不安全**（覆盖丢失），并发必须 ConcurrentHashMap（并发篇07）。

### ④ 为什么重写 equals 必须重写 hashCode

否则两个"相等"的对象 hashCode 不同 → 放进 HashMap 后 get 不到——**散列容器全靠 hashCode 定位桶、equals 确认相等**。

## 选型决策表

```
键值对 → HashMap（并发 CHM；有序 TreeMap/LinkedHashMap）
去重   → HashSet（有序 TreeSet）
列表   → ArrayList（几乎总是）
只读常量 → List.of()/Map.of()（不可变，防误改）
```

## fail-fast 与不可变集合

```java
for (String s : list) { if (...) list.remove(s); }   // ❌ ConcurrentModificationException
// modCount 被改 → 迭代器检测到 → 快速失败（设计：宁可报错不给脏数据）
// 正确：iterator.remove() / removeIf(条件) / 倒序 for 循环
List.of("a","b")          // 不可变集合（JDK9+）：add 抛异常——适合常量表
```

## 面试问法

**Q: HashMap 的 put 流程和扩容？**
A: hash 高低 16 位异或 → (n-1)&hash 定位桶 → 空桶 CAS 思路直接放 / 链表尾插 → 长度≥8 且表≥64 转红黑树。size 超 容量×0.75 → 扩容 2 倍：新位置只有两种可能（原位或原位+旧容量），无需重算 hash。JDK7 头插并发扩容死循环、8 尾插修复，但仍线程不安全 → ConcurrentHashMap。

**Q: ArrayList 和 LinkedList 怎么选？**
A: 默认 ArrayList：随机访问 O(1) + CPU 缓存局部性；LinkedList 的 O(1) 中间插删要先 O(N) 定位，实测全面落后。两端队列场景选 ArrayDeque 或 BlockingQueue。
