# 02 · 泛型、反射与注解：Spring 魔法的语言根基

Spring 的 @Autowired、@Transactional、@PostConstruct——全是靠 **反射 + 注解** 实现的。学懂这一篇，"Spring 是怎么做到的"就不再是魔法。

## 一、泛型：编译期的类型安全

```java
List<String> list = new ArrayList<>();
list.add("a");          // 只能放 String
// list.add(123);       // 编译期就报错
```

**关键认知：类型擦除**——泛型**只存在于编译期**，运行时 `List<String>` 和 `List<Integer>` 是同一个 Class（都是 `List`）：

```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());   // true！运行时无泛型信息
```

**推论（踩坑防雷）**：
- 不能 `new T()` / `new T[]`（运行时不知道 T 是什么）
- 不能对泛型类型用 instanceof
- 需要运行时类型 → 传 `Class<T>` 参数（各种 `JSON.parseObject(text, User.class)` 就是这个套路）
- **运行时想拿泛型信息** → 通过**父类/字段声明**留痕迹：`TypeToken`/`ParameterizedType`（Jackson 的 TypeReference 就是这么拿到 `List<User>` 的泛型的）

```java
new TypeReference<List<User>>() {}    // 匿名子类：把泛型信息"固化"在父类签名的字节码里
```

通配符：`? extends T`（只读生产者）/ `? super T`（只写消费者）——PECS 原则，了解即可。

## 二、反射：运行时"解剖"类

反射 = 在运行时读取/操作类的结构（字段/方法/构造器）。**Spring 的 @Autowired、@PostConstruct、MyBatis 的 Mapper 全是反射驱动的**：

```java
Class<?> clazz = Class.forName("com.example.User");
// 读注解
MyAnnotation anno = clazz.getAnnotation(MyAnnotation.class);
// 创建实例（调构造器）
Object obj = clazz.getDeclaredConstructor().newInstance();
// 读字段/改字段（连 private 都能改）
Field field = clazz.getDeclaredField("name");
field.setAccessible(true);            // 突破 private
field.set(obj, "张三");
// 调方法
Method m = clazz.getDeclaredMethod("say", String.class);
m.setAccessible(true);
Object result = m.invoke(obj, "你好");
```

**这就是 @Transactional 失效的根源**（并发篇03/事务篇）：Spring 拿到的是**代理对象**（CGLib 子类），`this.method()` 走的是原始对象——反射/代理的调用链 vs this 调用链不是一条路。

**反射的代价**：比直接调用慢（方法查找/装箱/安全检查），且绕过编译期检查。**框架内部可以用（一次性查找后缓存 Method 对象），业务代码不要用**。

## 三、注解：不打代码的"标签"

注解本身不做任何事——它是**贴在代码上的标签，等别人来读**（反射读取 或 编译期处理器处理）：

```java
// 注解的定义（元注解决定"贴在哪、留到何时"）
@Target(ElementType.METHOD)                    // 能贴在哪（METHOD/FIELD/TYPE/参数...）
@Retention(RetentionPolicy.RUNTIME)            // 保留到何时（RUNTIME 反射可读 / SOURCE 编译后丢弃 / CLASS）
public @interface AuditLog {
    String value() default "";
}

// 使用：@AuditLog("下单") —— 只是贴了标签，零副作用
// 处理器（反射读取标签做事）：
Method m = ...;
if (m.isAnnotationPresent(AuditLog.class)) {
    String op = m.getAnnotation(AuditLog.class).value();
    auditService.record(op);
}
```

**三个 Retention 的真实例子**：

| Retention | 例子 | 谁来处理 |
|-----------|------|---------|
| SOURCE | `@Override`、Lombok 的 `@Getter` | 编译期处理器（Lombok 改字节码） |
| CLASS | 字节码工具 | 字节码框架 |
| RUNTIME | `@Autowired` `@Transactional` `@Component` | Spring 启动时反射读取 |

**这就是 Spring 全家桶的原理**：@Component/@Autowired/@Transactional 全是 RUNTIME 注解——**容器启动时反射扫描 → 读取注解 → 执行对应逻辑（创建 Bean/注入依赖/织入事务代理）**。你写的每个注解，都有一个"读注解的处理器"在对应位置等着。

## 面试问法

**Q: 什么是类型擦除？运行时能拿到泛型信息吗？**
A: 泛型只在编译期做类型检查，运行时擦除为原始类型（List<String> 和 List<Integer> 同一个 Class）。推论：不能 new T/instanceof T。运行时拿到泛型的唯一途径是通过父类/字段的签名（ParameterizedType）——TypeReference/TypeToken 的原理。

**Q: 注解是怎么工作的？**
A: 注解本身零逻辑，是元数据标签；@Retention(RUNTIME) 的注解在运行时由处理器反射读取后执行对应逻辑——@Autowired 由 AutowiredAnnotationBeanPostProcessor 读、@Transactional 由事务拦截器读。SOURCE 级（Lombok）在编译期处理。**理解"注解=标签+处理器"就理解了整个 Spring 的注解驱动**。
