# 01 · 创建型：单例、工厂、建造者

解决"对象怎么创建"的三个模式。

## 一、单例：一个类全局只有一个实例

并发篇 03 讲过 DCL（双重检查锁），这里把**三种正确姿势**放一起对比：

```java
// 姿势1：静态饿汉——类加载机制天然线程安全（JVM 加锁保证 <clinit> 单线程）
public class ConfigHolder {
    private static final ConfigHolder INSTANCE = new ConfigHolder();   // 类加载时创建
    private ConfigHolder() {}
    public static ConfigHolder getInstance() { return INSTANCE; }
}
// 缺点：不用也加载（多数场景无碍；重资源单例才需要懒汉）

// 姿势2：DCL 懒汉（必须 volatile！防指令重排拿半成品——并发篇03）
public class Pool {
    private static volatile Pool instance;
    private Pool() {}
    public static Pool getInstance() {
        if (instance == null) {
            synchronized (Pool.class) {
                if (instance == null) instance = new Pool();
            }
        }
        return instance;
    }
}

// 姿势3：枚举——《Effective Java》推荐的终极答案
public enum Registry {
    INSTANCE;
    private final Map<String, Object> store = new ConcurrentHashMap<>();
}
// 天然防反射攻击（反射创建枚举直接抛异常）、防反序列化破坏、天然线程安全
```

**你项目里的单例**：Spring 容器的 Bean 默认都是单例（容器就是"单例工厂"，比你手写更强大——依赖注入+生命周期管理）。**面试答单例先说 Spring 单例注册表，再说手写三种，层次立刻高级**。

## 二、工厂：把"创建"从调用方剥离

痛点：调用方 `new MySQLDriver()` 写死了具体类——换 Oracle 要改代码。工厂让调用方只说"我要什么"，不关心"谁造的"：

```java
// JDK 的经典：DriverManager——你写 JDBC 时从没 new 过驱动类
Connection conn = DriverManager.getConnection(url, user, pass);
// 内部原理：各驱动 jar 在静态块里把自己注册进 DriverManager（SPI 机制）
// → 调用方只依赖 Connection 接口，驱动实现可插拔 —— 这就是 JDBC SPI（类加载篇讲过的打破双亲委派案例！）

// Spring 的 BeanFactory：IoC 容器本身就是超级工厂
// 你 @Component 声明，容器按"配方"创建——mq-mall 的 @Autowired 全靠它

// 简单工厂 vs 工厂方法 vs 抽象工厂（一句话分清）
//   简单工厂：一个工厂类 + if/switch 创建不同产品（小场景够用）
//   工厂方法：每个产品一个工厂类（新增产品不改老代码——开闭原则）
//   抽象工厂：创建"一族"相关产品（如 MySQL 的连接+语句+结果集 一族）
```

**与 MQ 呼应**：`DefaultRedisScript` 加载 Lua 脚本、`Jackson2JsonMessageConverter` 消息转换器——都是"把创建细节封装、调用方拿抽象"的工厂思想。

## 三、建造者：参数多到爆炸时的优雅构造

痛点：构造参数一大堆，全靠位置记忆（哪个是用户名哪个是密码？）：

```java
// ❌ 望远镜构造器：6 个连续 String/Long，错位了编译都不报错
new HttpRequest("POST", url, timeout, retry, headers, body);

// ✓ 建造者：链式调用，看名字知参数
HttpRequest req = HttpRequest.builder()
        .method("POST")
        .url(url)
        .timeout(Duration.ofSeconds(5))
        .header("Authorization", token)
        .body(body)
        .build();

// 你项目里的真实用例（到处都是）：
QueueBuilder.durable("order.queue").deadLetterExchange("dlx").ttl(5000).build();   // RabbitMQ 队列声明
new ThreadPoolExecutor(core, max, keepAlive, unit, queue, factory, handler);       // ← 反例：位置参数太长
ChatClient.builder(chatModel).build().prompt().user(msg).call().content();          // Spring AI 链式
BitFieldSubCommands.create().get(BitFieldSubCommands.BitFieldType.unsigned(31).valueAt(0));  // Redis BITFIELD
```

**Lombok 的 @Builder** 一行生成建造者；**Redis 的 QueueBuilder** 是建造者模式的工业范本——注意 RabbitMQ 拓扑声明全部走建造者（stage1 学 QueueBuilder.durable().lazy() 时你已经在用它了）。

手写建造者的骨架（面试可写）：

```java
public class HttpRequest {
    private final String method;       // 全 final → 不可变对象（并发安全免费送）
    private final String url;
    private HttpRequest(Builder b) { this.method = b.method; this.url = b.url; }
    public static Builder builder() { return new Builder(); }
    public static class Builder {
        private String method, url;
        public Builder method(String m) { this.method = m; return this; }   // 返回 this 支持链式
        public HttpRequest build() { return new HttpRequest(this); }
    }
}
```

## 三模式选型总结

| 模式 | 什么时候用 | 你身边的例子 |
|------|-----------|-------------|
| 单例 | 全局共享的无状态组件/池 | Spring Bean、Redis 连接池 |
| 工厂 | 创建逻辑复杂/需要可插拔实现 | DriverManager、BeanFactory、消息转换器 |
| 建造者 | 构造参数 4 个以上/可选参数多 | QueueBuilder、ChatClient、@Builder |

## 面试问法

**Q: 单例的几种写法？为什么要 volatile？**
A: 饿汉（类加载天然安全）、DCL 懒汉（volatile 防重排拿半成品）、枚举（防反射反序列化，Effective Java 推荐）。生产首选：交给 Spring 容器管理（单例注册表），手写场景选枚举或静态饿汉。
