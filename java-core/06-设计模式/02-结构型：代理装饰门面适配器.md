# 02 · 结构型：代理、装饰器、门面、适配器

四个模式都是"包装另一个对象"，区别在**包装的目的**。每个都用你已经学过的代码讲。

## 一、代理：控制访问（你已深学——AOP 全篇就是它）

```
调用方 → [代理：前置增强 → 目标 → 后置增强] → 真实对象
```

- **你学过的实例**：Spring AOP（@Transactional/日志切面）、Feign 的动态代理接口、Redisson 的锁包装
- 代理**与目标实现同一接口**，调用方无感知
- 详细机制见 [04-Spring 核心 02-AOP 原理](../04-Spring核心原理/02-AOP原理.md)（JDK/CGLib/失效场景全在那里），本篇不重复

一句话区分（易混考点）：**代理控制"能否/如何访问"（访问语义），装饰器增强"访问时的功能"（功能叠加）**。两者实现可以一模一样，意图不同。

## 二、装饰器：功能叠加（Java IO 的祖传设计）

层层包装、每层加一点功能、接口保持不变：

```java
// Java IO 经典——四层包装读一个带缓冲的文件
InputStream in = new BufferedInputStream(          // 装饰2：加缓冲（8KB）
                     new DataInputStream(           // 装饰1：加读基本类型
                         new FileInputStream("a.txt")));  // 核心：文件流

// 每层都是 InputStream → 装饰器与被装饰者同类型 → 可无限叠层
// 对比继承：BufferedFileDataInputNIOStream... 类爆炸！装饰器用组合替代继承
```

**你项目里的装饰器**：
- mq 教学里 `BufferedInputStream` 包 `FileInputStream`（读 binlog/文件示例）
- `redis.execute(script, keys, args)` 的 StringRedisTemplate：包装了底层 Connection 的能力
- Spring 的 `HttpServletRequestWrapper`：包装请求对象加"可重复读 body"能力（网关/日志场景常用）

**选型**：叠加式、可选式、同类型的功能增强 → 装饰器；控制访问 → 代理。

## 三、门面：给复杂子系统一个简单入口（你的项目里最典型）

子系统（库/表/交换机/消费者/补偿任务）很复杂，门面提供一个**简单的方法**把复杂性藏起来：

```java
// 你写的 ReliableMessagePublisher 就是教科书级门面：
// 内部复杂度：本地消息表写入 + 事务同步器 + Jackson 序列化 + Confirm/Return + 补偿任务
// 外部只看到一个方法：
publisher.sendInTransaction("mall.order", "order.created", messageId, event);
```

其它门面实例：

| 门面 | 藏住的复杂子系统 |
|------|-----------------|
| `DriverManager.getConnection()` | 驱动加载/连接参数/网络协议 |
| `JdbcTemplate` | 连接管理/Statement/异常转换/资源释放 |
| Redis 的 `GEOADD` | Geohash 编码 + ZSet 存储细节 |

**门面 vs 代理**：门面提供"新的简化接口"（接口变了）；代理保持"同一接口"（接口不变，只加增强）。

**与封装的关系**：门面就是"封装"上升到架构层——** subsystem 边界的 API 设计**。community 的 `ReliableMessagePublisher` 让业务代码"只传对象不操心序列化"（修坑一），正是门面价值的直接体现。

## 四、适配器：让不兼容的接口一起工作

适配器**转换接口**：已有的老接口 + 需要的新接口不匹配，中间垫一层转换：

```java
// JDK 经典：Arrays.asList(T...) 把数组适配成 List
// Spring MVC：HandlerMethodArgumentResolver 把 HTTP 请求"适配"成你的方法参数
// 你的项目：@FeignClient 接口把"HTTP 调用"适配成"方法调用"（OpenFeign 篇）
```

**适配器 vs 门面 vs 装饰器**（三兄弟一句话辨析）：
- **适配器**：接口不兼容 → 转换（"插头转换器"）
- **门面**：接口太复杂 → 简化（"一键遥控器"）
- **装饰器**：接口不变 → 加功能（"给手机贴膜"）

## 面试问法

**Q: 代理、装饰器、适配器、门面的区别？**
A: 都是"包装另一个对象"。代理：同接口，控制访问（Spring AOP）；装饰器：同接口，叠加功能（Java IO 缓冲流）；门面：提供简化的新接口，藏住子系统复杂度（ReliableMessagePublisher/JdbcTemplate）；适配器：转换不兼容接口（Feign 把 HTTP 适配成方法调用）。辨析题背"插头转换器/一键遥控器/贴膜"三比喻。
