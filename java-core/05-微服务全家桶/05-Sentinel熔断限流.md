# 05 · Sentinel：熔断、限流与降级

系统过载时的"保险丝 + 缓冲区"。Redis 教学 stage3/01 提过"DB 熔断限流兜底"，Sentinel 就是它的工业实现。

## 三大能力一句话

| 能力 | 一句话 | 对应漏斗 |
|------|--------|---------|
| **限流** | 超过阈值的请求直接拒绝 | 秒杀②层（网关限流） |
| **熔断** | 下游挂了就"跳闸"，一段时间不再调用（防雪崩） | 保护调用方 |
| **降级** | 跳闸期间返回兜底数据（默认值/缓存/简化版） | 用户看到降级页而非报错 |

## 限流：三种算法（Sentinel 都内置）

| 算法 | 原理 | 缺陷 | Sentinel 实现 |
|------|------|------|---------------|
| 固定窗口 | 每分钟计数≤100 | **窗口边界突刺**（两窗口交界瞬间可达 2 倍） | 默认 QPS 模式 |
| 滑动窗口 | 把窗口切成小格统计 | 内存开销略大 | `grade=RuleConstant.FLOW_GRADE_...` 统计结构 |
| **令牌桶** | 匀速生成令牌，桶满为止；请求拿令牌 | — | **匀速排队模式**（Slow request，rateLimitType） |
| 漏桶 | 匀速流出 | 无法容忍突发 | 同上排队模式 |

**滑动窗口示意**：1 分钟窗口切成 2 个 30 秒格子，判断"最近 1 分钟"时滑动取最近的格子求和——边界突刺消失。

## 熔断状态机（背这三态）

```
      失败率/慢调用比例 超阈值
关闭 ──────────────────────→ 打开（熔断中，直接拒绝所有请求）
 ↑                              │
 │        熔断时长结束            │
 └──── 半开（放少量探测请求）←────┘
        探测成功 → 关闭（恢复）
        探测失败 → 继续打开
```

**防雪崩的原理**：下游 D 挂了 → 上游调 D 的请求堆积 → 线程池占满 → **上游也被拖死** → 蔓延到调上游的服务……全链路雪崩。熔断 = 及时切断对 D 的调用，把故障隔离在 D。

## 降级：跳闸期间的兜底数据

```java
@SentinelResource(value = "getUser", blockHandler = "blockHandler", fallback = "fallback")
public User getUser(long id) {
    return userService.callRemote(id);        // 正常逻辑
}
// 被 Sentinel 限流/熔断时调用（规则触发）
public User blockHandler(long id, BlockException e) {
    return User.guest();                       // 返回默认视图
}
// 业务异常时调用（代码失败）
public User fallback(long id, Throwable e) {
    return cacheService.getFromLocal(id);      // 返回本地缓存旧数据
}
```

**降级的数据从哪来**：本地缓存旧值（stage3/01 多级缓存的第二层）/ 静态默认值 / 只读精简版页面——**"宁可数据旧，不要页面死"**。

## 与秒杀漏斗的组合（stage4/01 复盘）

```
前端(①) → 网关 Sentinel 限流(②：QPS 阈值) → Redis 预扣(③) → MQ(④)
                    ↑
        Sentinel 的降级：Redis 挂了 → 熔断 Redis 调用 → 降级为"同步查DB+强限流"（stage4/01 的降级预案）
```

## Sentinel 的特色：控制台动态改规则

```
下载 sentinel-dashboard jar → java -jar 启动 → 8080 控制台
应用接入：sentinel-starter + dashboard 地址
→ 控制台实时看 QPS 曲线 → 拖一下阈值立即生效（推到客户端内存）
```

**规则默认存内存**（重启丢失）→ 生产接 **Nacos 持久化规则**（规则变更从 Nacos 推送）——配置中心（02 篇）与熔断的组合使用。

## 与 Hystrix 的对比（选型一句话）

| | Hystrix（Netflix，停止更新） | Sentinel |
|--|----------------------------|----------|
| 隔离 | 线程池/信号量 | 信号量（轻量） |
| 规则 | 代码/配置，动态弱 | 控制台动态推送 + Nacos 持久化 |
| 生态 | 老旧 | SpringCloud Alibaba 原生、实时监控大盘 |

新项目直接 Sentinel。

## 面试问法

**Q: Sentinel 的限流算法和熔断机制？**
A: 限流算法：固定窗口（有边界突刺）、滑动窗口（切格消除突刺）、令牌桶/漏桶（匀速模式容忍突发排队）。熔断三态：关闭→(失败率/慢调用超阈值)→打开（直接拒绝防雪崩）→熔断时长结束→半开（探测）→成功关闭/失败再开。降级返回兜底数据（本地缓存/默认值）。规则支持控制台动态修改 + Nacos 持久化。防止下游故障沿调用链雪崩蔓延是熔断的核心价值。
