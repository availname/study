# 18 · 操作系统基础：把散落各处的 OS 知识收拢归位

> 🎯 **定位**：你工作区到处是 OS 知识的**影子**——线程池（上下文切换）、synchronized 重量级锁（内核互斥量）、Kafka 页缓存与零拷贝、Redis 的 epoll、虚拟线程（用户态线程）——但"进程线程/内核态/虚拟内存"这些**本体**从没正面对齐过。本篇是收拢篇：每个概念都"对号入座"到你已学的内容，不与 07 篇 IO 模型、Kafka 05 零拷贝重复展开。

## 一、进程与线程：一个是"资源单位"，一个是"调度单位"

```
进程（资源分配单位）                        线程（CPU 调度单位）
┌─────────────────────────────┐
│ 进程地址空间（虚拟内存）        │   ┌─ 线程1：私有栈 + 寄存器 + PC
│ ┌─────────┐  ┌───────────┐  │   ├─ 线程2：私有栈（堆是共享的！）
│ │ 代码/数据 │  │  堆（共享）  │  │←──┤
│ └─────────┘  └───────────┘  │   └─ 线程3：私有栈
│ 文件描述符表/socket 等资源      │
└─────────────────────────────┘
```

| 维度 | 进程 | 线程 |
|------|------|------|
| 内存 | **独立**地址空间（隔离的根） | 共享进程堆，**仅栈/寄存器私有** |
| 切换成本 | 高（要切页表，TLB 全失效） | 低（同进程内只换寄存器+栈） |
| 崩溃影响 | 互不影响（进程隔离） | 一个崩整个进程崩 |
| 通信 | IPC（管道/共享内存/socket） | 直接读写共享变量（←所以要并发控制！） |

**对号入座**（这就是 JMM 的物理基础）：①"多线程共享堆内存"= 上图共享区——所以才有 [JMM 与 volatile](01-并发编程/03-volatile与JMM内存模型.md) 解决可见性、[锁](01-并发编程/02-synchronized与锁原理.md) 解决互斥；②[ThreadLocal](01-并发编程/07-并发容器与ThreadLocal.md) 的"线程私有"= 线程私有栈/寄存器空间的编程延伸；③**虚拟线程 = 用户态线程**：把"线程"从内核搬到 JVM 用户态，阻塞时 unmount 让出载体线程（[stage6/01](../stage6-新技术专题/01-VirtualThreads虚拟线程.md)）——本质是把 OS 线程 1:1 映射改成 M:N 映射，绕开内核调度成本。

**为什么上下文切换贵**（[线程池](01-并发编程/05-线程池ThreadPoolExecutor.md)"线程不是越多越好"的根）：切进程要换页表（TLB 缓存全作废）；切线程要保存/恢复寄存器组；**更要命的是 CPU 缓存失效**——切换后热数据全要重新拉内存。单次切换 1~10μs，高并发下"线程数 > 核数"时大部分 CPU 时间花在切换而不是干活。

## 二、用户态与内核态：一切的"过路费"

```
用户态（你的 JVM 代码跑在这）        内核态（OS 内核跑在这，权限最高）
      │  系统调用/中断                  │
      ├──────→ read()/write()/mmap() ──→ 真正操作硬件（磁盘/网卡）
      ←──────  切换回来（保存/恢复现场） │
```

**何时切换**：系统调用（read/write/fork）、中断（磁盘 IO 完成/时钟）、异常（缺页）。

**成本**：保存用户态寄存器+切换页表+内核执行+恢复——**每次约 1~5μs**。

**对号入座**：①`synchronized` 重量级锁 = 内核**互斥量**（mutex），阻塞唤醒都过内核（[锁升级](01-并发编程/02-synchronized与锁原理.md)：所以偏向/轻量级锁先用 CAS 避免进内核）；②Kafka [零拷贝](../mq/stage5-Kafka专篇/05-Kafka高性能读写原理.md)说的"4 次切换"就是 4 次过这道费；③虚拟线程 pinning 的根源也在"阻塞点是否进内核"（JDK21 synchronized 内阻塞无法 unmount）。

## 三、虚拟内存：进程隔离与 PageCache 的本体

**每个进程看到的是独享的连续地址空间**，由 OS 通过页表把虚拟地址映射到物理内存/磁盘：

```
进程A 虚拟地址 0x7f00... ──页表──→ 物理内存帧
        （未映射/被换出）──→ 触发【缺页中断】→ 内核从磁盘调入 → 你的代码无感知
```

三个你要懂的推论：

1. **隔离**：进程 A 根本无法直接访问进程 B 的页表映射——这就是"进程独立地址空间"的实现机制（服务多进程部署互不干扰的根）
2. **PageCache 就是内核页**：Kafka/Redis 说的页缓存 = 内核把**磁盘页**缓存在空闲物理内存里——同一份数据读写都命中它（[Kafka 05 原理二](../mq/stage5-Kafka专篇/05-Kafka高性能读写原理.md)）
3. **mmap = 把文件映射进虚拟地址空间**：绕过 read 系统调用，像访问内存一样访问文件（Kafka 索引文件用它的原因：随机访问友好 + 免一次拷贝）；**Java 堆外内存**（DirectByteBuffer，Netty 默认用）就是用户态版的"绕开 JVM 堆管理"

> [!TIP]
> 一条主线串起来：**"内存太贵 + 太小"是所有存储优化的源动力**——虚拟内存用磁盘扩容物理内存，PageCache 用空闲内存缓存磁盘，Redis 干脆把数据放内存，Kafka 用顺序写+页缓存让磁盘发挥内存级吞吐。你在 mq/redis 学的所有"快"，背后都是同一道物理题。

## 面试问法

**Q: 进程和线程的区别？**
A: 进程是资源分配单位（独立虚拟地址空间，崩溃隔离），线程是调度单位（共享进程堆，仅栈/寄存器私有）。切进程要换页表、TLB 失效成本高；切线程只换寄存器和栈。线程共享堆是 JMM 可见性/锁/ThreadLocal 问题的物理根源；虚拟线程把线程从内核态搬到用户态（M:N 映射）绕开调度成本。

**Q: 用户态和内核态是什么？为什么有区分？**
A: 内核态跑 OS 内核、独占硬件操作权；用户态跑应用，只能通过系统调用请求内核服务。区分是**保护**：应用崩溃/越权不伤及系统。代价是每次系统调用 1~5μs 现场切换——所以有零拷贝（减少搬运+切换）、锁升级（CAS 先行避免内核互斥量）、epoll（一次系统调用监听万级 fd）这些优化方向。

**Q: 虚拟内存是什么？**
A: OS 给每个进程独享的连续虚拟地址空间，由页表映射到物理内存/磁盘，未映射的页访问触发缺页中断由内核调入。价值：进程隔离（A 访问不到 B）、内存超售（磁盘当内存后备）、PageCache/Mmap 这类机制的基础——Kafka 索引用 mmap、页缓存就是内核页。
