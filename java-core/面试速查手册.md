# 面试速查手册（全模块高频题汇总）

> 用法：面试前过三遍。每题给**答题骨架**（要点顺序），展开细节回对应教程章节。
> 标 ⭐ 的是出现率最高的题。口述标准：每题能流畅讲 60~90 秒。

## 一、并发编程（java-core/01）

**⭐1. synchronized 原理与锁升级？**
对象头 Mark Word 存锁状态 + Monitor（Owner/EntryList/WaitSet）→ 升级链：偏向锁（单线程免CAS，JDK15废弃）→ 轻量级（CAS自旋，交替竞争）→ 重量级（OS互斥量，激烈竞争）。可重入靠计数器。附带可见性保证（进出同步块刷主存）。

**⭐2. volatile 作用？能替代锁吗？**
可见性（写刷主存+使其它核缓存失效，lock 前缀指令）+ 有序性（内存屏障禁重排，DCL 单例必加）；**不保证原子性**（count++ 仍交错）。不能替代锁——复合操作用锁或 CAS。判断依据：happens-before 规则链。

**⭐3. 线程池七个参数与执行流程？**
core/max/keepAlive/unit/workQueue/threadFactory/handler。流程：核心未满建核心 → 满则入队 → 队满建临时到 max → 仍满触发拒绝。**先排队后扩容**——所以无界队列让 max 失效（Executors 坑，OOM）。生产：手写参数+有界队列+自定义拒绝（日志/落库/告警）+ 动态调参。

**⭐4. CAS 是什么？ABA 怎么解决？**
CPU 原子指令（比较+交换一步）。问题：①ABA（值回旧值但历史已变→AtomicStampedReference 版本号）②自旋耗 CPU（LongAdder 分段）③单变量限制。分布式同思想：乐观锁版本号。

**5. ThreadLocal 内存泄漏？**
Thread→ThreadLocalMap，key 弱引用（可回收变 null）、value 强引用——线程池线程不死则 value 泄漏。规约：finally remove()。另：不能跨线程传递。

**6. ConcurrentHashMap JDK8 怎么保证并发安全？**
空桶 CAS、非空桶 synchronized 锁头节点（粒度=桶）；红黑树防碰撞攻击；多线程协同扩容；CounterCell 分段计数（LongAdder 思想）。不允许 null。

**7. 死锁四条件与排查？**
互斥/持有等待/不可剥夺/循环等待。排查：jstack 找"deadlock"、Arthas thread -b。预防：固定加锁顺序、tryLock 超时、缩小锁粒度。

**8. 虚拟线程是什么？（stage6/01）**
JVM 用户态线程：阻塞时 unmount 让出载体线程（核数个），KB 级可百万。Boot3.2 一行开启。JDK21 有 synchronized pinning；瓶颈转移到连接池；不池化。

## 二、JVM（java-core/02）

**⭐1. 内存区域？哪些共享？**
共享：堆（Eden+2Survivor/老年代）、元空间（类信息，本地内存）。私有：虚拟机栈（栈帧）、本地方法栈、程序计数器。异常：堆 OOM heap space、元空间 OOM、栈 StackOverflowError。

**⭐2. 对象什么时候可以被回收？**
可达性分析：GC Roots（栈变量/静态/常量/JNI/活跃线程）不可达即垃圾。不用引用计数（循环引用）。四引用弹性：软（缓存内存不足）、弱（ThreadLocal key）、虚（堆外管理）。

**⭐3. G1 和 CMS 区别？为什么 G1 成默认？**
CMS：标记清除→碎片+并发失败退化。G1：堆 Region 化（2048 块），逻辑分代，按回收收益/成本挑 Region，MaxGCPauseMillis 停顿目标模型，无碎片。ZGC 再进一步：着色指针，亚毫秒停顿与堆大小无关。

**⭐4. CPU 100% 怎么排查？**
top 定进程 → top -Hp 定线程 → 线程 ID 转 16 进制 → jstack 对应堆栈。常见：死循环/频繁 GC/正则回溯。Arthas `thread -n 3` 一步到位。

**5. 类加载过程与双亲委派？**
加载→验证→准备（静态零值）→解析→初始化（<clinit>，JVM 加锁）。双亲委派：先委派父加载器——安全（核心类不可篡改）+不重复。打破：SPI 线程上下文加载器、Tomcat 隔离。

**6. 内存泄漏怎么排查？**
判定：Full GC 后水位不回落且抬升。jmap dump（OOM 自动 dump 先配）→ MAT 支配树 → 凶手常见：无界缓存/ThreadLocal/监听器/连接。修复：上限/TTL/remove。

## 三、MySQL（java-core/03）

**⭐1. 为什么用 B+ 树？**
磁盘 IO 是瓶颈：B+ 非叶子只存键（16KB 页放更多键，千万行 3~4 层）；叶子链表支持范围查询。对比：哈希无范围、二叉太高 IO 多、B 树非叶子带数据树更高。

**⭐2. 什么是回表/覆盖索引？最左前缀？**
二级索引叶子只存（索引列+主键）→ 查非索引列需拿主键回聚簇树再查=回表。查询列全在索引=覆盖（Using index）。联合索引按第一列排——最左前缀原则，范围列之后的列失效。

**⭐3. 事务隔离级别？MVCC 原理？**
RU/RC/RR（默认）/串行化。MVCC 三件套：隐藏列（trx_id/roll_pointer）+ undo 版本链 + ReadView（活跃名单）。可见性判定：trx==自己✓ / <min✓ / ≥max✗ / 在名单✗。**RC 每次读新 ReadView，RR 只首次**——可重复读的实现。

**⭐4. 索引失效场景？**
函数/运算包裹列、隐式类型转换（varchar=数字）、左模糊 like、OR 侧无索引、≠/not in（优化器理性放弃）。诊断 EXPLAIN：type=ALL 全表、key=NULL、rows 大。

**5. redo/undo/binlog 区别？两阶段提交为什么？**
redo（InnoDB 物理，循环写，crash-safe）/undo（逻辑反操作，回滚+MVCC）/binlog（Server 逻辑，追加，复制+CDC）。两阶段提交（redo prepare→binlog→commit）保证 redo 与 binlog 一致→主从一致。双 1 配置基本不丢。

**6. 分库分表什么时候做？分片键怎么选？**
三线：单表 2000 万/写 QPS 到顶/磁盘告急——先缓存后读写分离。分片键按查询维度：user_id（用户维度）+ 冗余 seller_id 表（卖家维度）+ order_id 表（直查）。代价：分布式 ID/跨片查询/跨片事务/扩容迁移。

**7. 死锁怎么排查预防？**
SHOW ENGINE INNODB STATUS 看 LATEST DEADLOCK；8.0 查 data_lock_waits。预防：短事务、按固定顺序加锁、更新走索引、防重用唯一索引替代"先查后插"（间隙锁共存会互堵）。

**8. 大表深分页？**
LIMIT 100万,10 扫 100 万行丢弃。方案A 键集游标：WHERE id>上页末尾 LIMIT 10（最优）；方案B 延迟关联：子查询覆盖索引取 id 再回表。

## 四、Redis（redis/stage3、stage4）

**⭐1. Redis 为什么快？**
内存 + 命令执行单线程（无锁无切换）+ epoll 多路复用（事件驱动）+ 高效数据结构（SDS/跳表/listpack）。6.0 IO 多线程但命令仍单线程。代价：慢命令阻塞全端（禁 KEYS、防大 Key）。

**⭐2. 缓存穿透/击穿/雪崩？**
穿透（查不存在）→空值缓存+布隆过滤器+参数校验；击穿（热点过期瞬间）→互斥锁重建/逻辑过期；雪崩（大面积同时失效）→TTL 抖动+多级缓存+高可用+DB 熔断。监控命中率。

**⭐3. 缓存与 DB 一致性？**
Cache Aside：读-未命中回写（带 TTL）；写-先更 DB 再删缓存（删除幂等无覆盖问题）。残留窗口极小，高要求加延迟双删（MQ 延迟）；复杂系统 binlog（Canal）→MQ→删缓存零侵入。强一致场景放弃缓存。

**⭐4. 分布式锁怎么实现？**
SET key requestId NX EX 原子抢锁；释放 Lua 校验 requestId（防误删他人锁）；看门狗续期（Redisson）。主从切换可能双持锁→正确性场景 DB 兜底（乐观锁/唯一索引），Redis 锁是效率层。

**⭐5. 大 Key/热 Key？**
大 Key（String>10KB/集合>5000）：阻塞全端、删除危险（UNLINK）、Cluster 不均——发现 --bigkeys，治理分桶/拆分/上限。热 Key（单 key QPS 极高）：本地缓存+读写分离+热写打散。

**6. 持久化 RDB vs AOF？**
RDB 全量快照（文件小恢复快，分钟级丢），fork+COW；AOF 命令日志（everysec 丢 1 秒，重写压缩）。生产双开+混合持久化（AOF 重写 base 用 RDB 格式）。

**7. 主从/哨兵/集群？**
主从异步复制（切换丢尾部数据）；哨兵三态（主观下线→客观下线→选主），3 个奇数；Cluster 16384 槽分片（CRC16%16384），多 key 同槽哈希标签。容量够用选哨兵、超大选 Cluster 或云托管。

**8. RedLock 了解吗？为什么生产不用？**
向 5 个独立 Redis 过半抢锁的多数派方案，试图解决主从切换丢锁。Martin 指出两个缺口：GC 停顿下锁过期后客户端恢复继续写（任何锁都有）；依赖时钟准确（NTP 跳变可绕过）。工程结论：效率锁 Redisson 单实例足够；正确性锁靠存储层 CAS/唯一索引（**fencing token** 思想）；跨服务协调用 ZooKeeper/etcd——Redisson 已废弃 RedLock（[redis stage3/05](../redis/stage3-问题解决/05-RedLock争议与FencingToken.md)）。

## 五、MQ（mq/ 全部）

**⭐1. 为什么用 MQ？三大作用？**
异步提速（490ms→52ms）/解耦（新下游零改动）/削峰填谷（洪峰进队列匀速消费）。不该用：强一致同步、需要即时结果、QPS 极低系统。

**⭐2. 消息丢失怎么防？（三端）**
生产：Confirm+失败补偿，强可靠用本地消息表（业务+消息同事务，afterCommit 发送，定时补偿）；Broker：持久化+刷盘+副本；消费：手动/AUTO ACK+重试+死信。极端窗口（Confirm 丢失）由补偿兜底，重复由幂等拦截。

**⭐3. 消息重复怎么幂等？**
重复不可避免（at-least-once），业务幂等两层：Redis setnx 快去重（24h TTL，失败回滚键）+ DB 唯一索引兜底；天然幂等优先（状态机 CAS/ON DUPLICATE UPDATE）。注意幂等键用全局唯一业务 ID（内存计数器重启撞号）+幂等跳过打日志。

**⭐4. 消息顺序怎么保证？**
只需业务分区有序。RocketMQ：MessageQueueSelector 按 key 选队列+Orderly 消费；Kafka 分区内有序（key 路由+重试乱序注意）； RabbitMQ 单队列单消费者。或业务侧版本号丢弃（旧版本直接丢）。

**5. 消息堆积怎么办？**
定位（消费者挂/慢/生产暴涨）→修复瓶颈→扩容三步（扩队列+搬运+扩消费者）→过期消息丢弃补偿。预防：批量消费+限速保护下游+监控告警。

**6. 延迟消息怎么做？**
RabbitMQ：TTL+DLX（队头阻塞→按档位拆队列）或延迟插件；RocketMQ：18 等级/5.x 任意时间。订单超时场景：延迟消息+扫表双保险，CAS 防与支付竞态。方案选型全景（DelayQueue/扫表/ZSet/过期通知/时间轮）见[延迟任务专题](../mq/延迟任务方案横向对比.md)。

**7. 事务消息/最终一致？**
本地消息表（业务+消息同事务，补偿重发）→ RocketMQ 半消息（内置）：半消息落盘但消费者不可见→执行本地事务→commit/rollback→宕机靠 Broker **回查** checkLocalTransaction（本质=服务端内置的本地消息表，[stage6 专篇](../mq/stage6-RocketMQ专篇/01-RocketMQ架构与事务消息.md)）。选型：同步短链路强一致 Seata AT；异步长链路 MQ 最终一致；资金 TCC。消费端幂等永远要有。

**8. Kafka 为什么快？**
五支柱：①**顺序写**（日志追加，磁盘顺序 600MB/s 比随机快 3~4 个量级）②**页缓存**（走 OS PageCache 不进 JVM 堆，零 GC）③**零拷贝**（消费 sendfile，4 拷贝 4 切换→2 拷贝，SSL 失效）④**批量+压缩**（攒批摊薄开销+整批压缩）⑤**分区并行**（Partition 是并行单位）+稀疏索引。总纲：随机读写→顺序读写，多次搬运→最少搬运（[Kafka 05](../mq/stage5-Kafka专篇/05-Kafka高性能读写原理.md)）。

## 六、Spring（java-core/04）

**⭐1. Bean 生命周期？**
实例化→属性注入→Aware→BPP前→初始化（@PostConstruct→afterPropertiesSet→init-method）→BPP后（AOP 代理生成处）→使用→销毁。

**⭐2. 循环依赖三级缓存？**
一级成品/二级早期引用/三级工厂（延迟决定 AOP 代理）。字段注入可解、构造器注入无解（@Lazy）。三级而非两级：延迟判断"是否提前代理"。

**⭐3. AOP 失效场景？**
万变不离"没走代理"：自调用 this、非 public、final/static、new 出来的对象、注解标接口（CGLib）。修复：拆 bean/注入自己@Lazy/getBean。

**⭐4. @Transactional 失效八连？**
自调用/非 public/异常被吞/默认不回滚受检异常（rollbackFor）/多线程（ThreadLocal 连接）/传播误用/MyISAM/类不受管理。事务=ThreadLocal 绑定连接，afterCommit 再发 MQ。

## 七、微服务（java-core/05）

**⭐1. Nacos 注册中心原理？**
临时实例心跳 5s（AP/Distro）+ 持久实例服务端探测（CP/Raft）；保护阈值防全摘除。配置中心长轮询 29.5s 准实时刷新（@RefreshScope）。

**⭐2. Feign 注意什么？**
声明式 HTTP（代理+服务发现+负载均衡）。超时显式配、**写接口禁自动重试**（重试放大写，下游幂等兜底）、RequestInterceptor 传登录态/traceId、集成 Sentinel fallback 降级。

**⭐3. Sentinel 限流熔断？**
限流算法（固定/滑动/令牌桶漏桶）；熔断三态（关闭→打开→半开探测）；降级返回兜底（本地缓存/默认值）。规则控制台动态推送+Nacos 持久化。防下游故障沿链路雪崩。

**⭐4. Seata AT 原理？**
两阶段+undo_log：一阶段记录前后镜像+业务 SQL 直接本地提交；全局回滚按前镜像反向补偿（校验后镜像防脏写=CAS）。对比本地消息表：准实时强一致 vs 最终一致；同步短链路 AT、异步长链路 MQ。

**⭐5. XXL-Job 原理？和 @Scheduled 区别？**
调度与执行分离：调度中心集群 DB 行锁抢占保证一次触发单节点发起；执行器内嵌 handler，HTTP 上报结果。@Scheduled 多实例重复跑、无重试告警。XXL-Job 补：动态增删、失败重试+告警、**分片广播**（id % shardTotal = shardIndex）、故障转移路由（[07 篇](05-微服务全家桶/07-XXL-Job分布式任务调度.md)）。

## 十、监控与 AI 应用（java-core/13-04、stage7）

**⭐1. 监控告警怎么做？** → 三支柱 Metrics/Tracing/Logs；四黄金指标（延迟看 **P99** 不看均值/流量/错误率/饱和度）+业务大盘（支付成功率）；Micrometer→Prometheus→Grafana；告警纪律：持续超阈值+每条可执行+分级+静默防风暴（[13/04 篇](13-运维部署实战/04-监控告警与Metrics.md)）
**⭐2. RAG 和微调怎么选？** → 知识更新频繁→RAG（可溯源、改文档即生效）；行为/风格/领域语感压不稳→微调。顺序：提示工程→RAG→微调，可叠加。LoRA=冻结 W 只训低秩旁路 B·A（QLoRA 单卡可跑），部署 OpenAI 兼容端点调用方只换 base-url（[stage7/09](../stage7-AI应用开发/09-AI微调与选型.md)）
**⭐3. 提示注入怎么防？** → 直接+间接（RAG/工具带进来的外部数据埋指令，类比 SQL 注入）；防御纵深：提示词边界（不彻底）→**架构层权限最小化（最有效）**→输出过滤→高危操作人工确认（[stage7/08](../stage7-AI应用开发/08-AI安全与评测.md)）

## 十一、工程规范与 OS 基础（java-core/16、17、18）

**⭐1. 日志规范怎么定的？** → slf4j 门面+logback 禁 System.out；六要素（时间/级别/线程/traceId/位置/业务键值）；级别即责任（ERROR 配告警必须人跟进、跳过路径也打日志）；占位符不拼接、异常作最后参打全堆栈、全局异常处理器统一 ERROR；MDC traceId 全链路（MQ 随消息头传）；AsyncAppender 宁丢日志不堵业务（[17 篇](17-日志规范.md)）

**⭐2. 接口设计怎么规范？** → URI 名词复数+层级从属，动作用"子资源+动词"（`/orders/{no}/pay`）；动词幂等表（PUT/DELETE 幂等，POST/PATCH 非）；状态码语义+统一响应体 `{code,msg,data}`；错误码按模块分段；列表三件套分页/排序/过滤（[16 篇](16-接口设计规范.md)）

**3. 进程和线程的区别？** → 进程=资源分配单位（独立虚拟地址空间、崩溃隔离），线程=调度单位（共享堆、私有栈/寄存器）；切进程换页表 TLB 失效贵，切线程只换现场。线程共享堆是 JMM/锁/ThreadLocal 问题的物理根源；虚拟线程=用户态线程 M:N 映射（[18 篇](18-操作系统基础.md)）

**4. 用户态/内核态？虚拟内存？** → 内核态独占硬件，用户态经系统调用请求（每次 1~5μs）——零拷贝/锁升级/epoll 全是省这道过路费；虚拟内存=每进程独享地址空间由页表映射物理内存（隔离的根），PageCache/mmap 都建立在它之上

## 十二、登录态与接口安全（java-core/19）

**⭐1. Session / Redis Token / JWT 怎么选？** → 存储位置（内存/Redis/客户端）+ 扩展性（粘性会话/Redis 共享/天然无状态）+ 可撤销性（前两者 DEL 即刻生效；JWT 收不回——黑名单/短过期+刷新令牌/版本号本质是把状态加回来）。单体用 Redis Token，微服务 JWT+15min 短过期网关统一验签（[19 篇](19-登录态与接口安全.md)）
**⭐2. JWT 为什么无法真正登出？** → 服务端不存状态，验签只证"未篡改"不证"已注销"——无状态与可撤销是根本矛盾；解法：短过期+refresh token（Redis 可撤销）/黑名单（TTL=剩余有效期）/用户级 tokenVersion
**3. JWT 的 Payload 是加密的吗？** → ❌ Base64URL 只是编码！手机号/密码放 Payload=裸奔；签名只防篡改不防读；密钥泄露=全线失守（生产 RS256 非对称）
**⭐4. 密码怎么存？MD5 加盐行不行？** → ❌ 速度太快 GPU 秒破；BCrypt/Argon2=每用户随机盐（嵌在哈希串）+慢哈希 cost 12 约 250ms，撞库从拼运气变拼算力；前端预 MD5 无意义，传输靠 HTTPS
**⭐5. 越权怎么防？** → 水平越权（改 ID 查别人数据）：信任的只有登录态 userId，SQL 直接 `where user_id=?` 或查出后校验归属；垂直越权：拦截器之上加角色校验（RBAC/@PreAuthorize）；401 未认证跳登录 vs 403 无权限
**6. 接口重放怎么防？** → timestamp ±5min 窗口 + nonce Redis SETNX 单次有效 + 参数排序 HMAC 签名；有成本（多一次 Redis 写），只给开放接口/支付回调上，内部服务不套用

## 十三、K8s 入门（java-core/13-05）

**⭐1. K8s 和 Docker Compose 的区别？** → Compose=单机"启动脚本"（命令式）；K8s=集群"期望状态控制器"（声明式）——声明 replicas=2，控制器持续对齐：机器挂自动迁移（自愈）、发版自动滚动、扩容改数字。与支付状态机 CAS 同源：声明期望，差异驱动动作（[13-05 篇](13-运维部署实战/05-Kubernetes入门-从Compose到容器编排.md)）
**⭐2. Pod / Deployment / Service 什么关系？** → Pod=最小调度单位（1~N 共享网络的容器）；Deployment=管副本数与滚动更新（新 ReplicaSet 逐个替换，readiness 探针保证不中断，rollout undo 一行回滚）；Service=一组 Pod 的稳定虚拟 IP+负载均衡（Nacos 服务发现的内置版）
**3. liveness vs readiness 探针？** → liveness 失败=重启（治假死/死锁）；readiness 失败=摘出 Service 不接流量但不重启（治预热/过载）；发布时 readiness 是滚动更新不 502 的关键；配 Actuator health 端点
**4. 应用上 K8s 要改什么？** → 容器随时可死可迁（不可变基础设施）→ 本地状态外置：登录态 Redis Token、定时任务 XXL-Job/CronJob 防重复、本地缓存换 Redis、文件上对象存储——云原生"天生用 Redis"是容器生命周期倒逼的
