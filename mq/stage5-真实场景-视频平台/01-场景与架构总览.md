# Stage 5 · 真实场景：视频平台的内容处理流水线

> 你在 B 站/抖音点"发布"按钮的一瞬间，背后发生了一场肉眼看不见的接力赛。
> 这一阶段用 [mq-mall](../mq-mall/README.md) 里的 `media` 包**真实跑通**这条流水线。

## 场景：视频上传后发生了什么

用户视角：点上传 → 进度条走完 → 几分钟后视频"发布成功"。

系统视角（你点发布之后，服务器要做的事）：

```
1. 转码：一个 500MB 的原始视频 → 360p/720p/1080p/4K 多码率版本（FFmpeg，分钟级）
2. 审核：AI 识别违规内容（涉黄/涉暴/广告）→ 拿不准的进人工审核队列
3. 上架：CDN 预热、抽封面、生成播放列表
4. 广播：推荐索引入库、粉丝推送（UP 主百万粉丝 = 洪峰）
```

每一项都是**重活、慢活、还可能失败**。它们和"订单创建"有本质区别：

| 对比 | 订单场景（stage4） | 视频处理场景（stage5） |
|------|-------------------|----------------------|
| 时效要求 | 秒级（用户在等） | 分钟级（用户能接受"转码中"） |
| 任务耗时 | 毫秒级落库 | 每步秒~分钟级重计算 |
| 失败处理 | 重试 + 死信人工 | 重试 + **人工重提**（可修复后重跑） |
| 一致性 | 资金/库存，强约束 | 最终一致，状态机推进 |
| MQ 用法 | 削峰 + 事件通知 | **任务管道（队列串联）+ 结果广播** |

**如果没有 MQ**：上传接口同步执行转码 → 用户挂在"上传中"5 分钟；转码服务崩了 → 视频永远卡死；想加"自动生成字幕"环节 → 改上传代码重新发布。三个灾难。

**有了 MQ**：上传接口 50ms 返回 videoId，剩下的活儿排队慢慢干——这就是"任务管道"。

## 总架构（对应 mq-mall 的 media 包）

```
POST /api/videos（模拟上传完成，秒回 videoId）
   │  本地消息表 + 事务（复用 stage3/01 基建）
   ▼
media.submitted.queue
   │ ①转码消费者（sleep 模拟 FFmpeg 1.5s；含 FAIL 的确定性失败→重试→人工重提）
   ▼
media.transcoded.queue
   │ ②审核消费者：BLOCK→REJECTED ∥ HUMAN→HUMAN_AUDIT(人工卡点) ∥ 通过→③
   ▼
media.audited.queue
   │ ③上架消费者（CDN 预热）
   ▼
media.published.fanout ──┬── media.recommend.queue → 推荐索引入库
                         └── media.notify.queue   → 粉丝推送（分批限速）
```

状态机（DB 驱动，CAS 推进，存在 `t_media_task` 表）：

```
UPLOADED → TRANSCODING → TRANSCODED → AUDITING ─┬→ AUDITED → PUBLISHED
              │                                  ├→ REJECTED（AI 拒绝）
              │                                  └→ HUMAN_AUDIT →（人工端点）→ AUDITED / REJECTED
              └→ FAILED（转码失败，/api/videos/{id}/retry 人工重提）
```

**每一级状态推进都用 CAS**（`UPDATE ... WHERE status=期望值`）——重复消息、乱序消息、并发重试全部天然安全。这套纪律和订单场景（stage4/02）一模一样，**这就是方法论：状态机 + CAS 是异步系统的通用防火墙**。

## 动手玩（应用启动后）

```bash
# 正常视频：几秒后 PUBLISHED，fanout 两个下游都有日志
curl -X POST "http://localhost:8090/api/videos" --data-urlencode "title=Spring教程第1集"

# 必失败：转码 3 次重试后 FAILED → /retry 重提（依然失败——确定性故障，教学用）
curl -X POST "http://localhost:8090/api/videos" --data-urlencode "title=FAIL转码测试"

# 审核拒绝：BLOCK 关键词 → REJECTED
curl -X POST "http://localhost:8090/api/videos" --data-urlencode "title=BLOCK违规内容"

# 人工卡点：HUMAN 关键词 → 停在 HUMAN_AUDIT → 人工端点放行
curl -X POST "http://localhost:8090/api/videos" --data-urlencode "title=HUMAN边缘内容"
curl -X POST "http://localhost:8090/api/videos/{videoId}/audit" --data-urlencode "pass=true"

# 轮询状态 / 查看大盘
curl "http://localhost:8090/api/videos/{videoId}"
curl "http://localhost:8090/api/videos/stats"
```

> 注意：curl 传中文参数必须用 `--data-urlencode`（放进 URL 查询串会因 RFC 3986 非法字符被 Tomcat 直接 400——这也是我们真实踩到的坑，见[踩坑实录](../踩坑实录-完整复盘.md)）。
