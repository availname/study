# 02 · 排行榜、签到与 UV 统计（特殊类型实战）

Stage 1 认识了 Bitmap/HLL/ZSet，本章用**真实业务需求**把它们串成一套方案（demo 的 `/rank` `/sign` `/uv` 接口）。

## 一、实时排行榜（ZSet）

### 基本盘

```java
// 加分（原子）
redis.opsForZSet().incrementScore("rank:game:2026", player, delta);
// 前三名（含分数）
Set<ZSetOperations.TypedTuple<String>> top =
    redis.opsForZSet().reverseRangeWithScores("rank:game:2026", 0, 2);
// 我的排名与分数
Long myRank = redis.opsForZSet().reverseRank(key, player);   // 0 开始
Double myScore = redis.opsForZSet().score(key, player);
```

### 真实榜单的三个工程问题

**① 同分怎么排名次？**
score 拼接技巧：`score*1e6 + (maxTimestamp - now)`——分数优先、时间早者靠前。或 Redis 6.2+ `ZRANK ... WITHSCORES` 直接支持同分按字典序。

**② 榜单无限增长 → 大 Key（stage3/04）**
按月/赛季分 key：`rank:game:202611`；`ZREMRANGEBYRANK key 0 -(N-100)` 只留前 100 名。

**③ 全量用户都想看自己的名次（千万级）**
`ZREVRANK` O(logN) 没问题，但榜单只展示前 100 + "我的排名"接口按查——**不要把千万级榜单全量返回**。

### 热搜榜（时间衰减）

分数 = 热度值 × 衰减因子。简单做法：定时任务对全榜 `ZADD` 乘 0.95（分钟级衰减），或 score 混合"热度+时间戳"编码。

## 二、签到日历（Bitmap）

```java
// 签到：key=用户+月份，offset=日期-1
redis.opsForValue().setBit("sign:1001:202611", day-1, true);
// 本月签到天数
Long days = redis.opsForValue().bitCount("sign:1001:202611");
// 今天签了吗
Boolean signed = redis.opsForValue().getBit("sign:1001:202611", day-1);
```

连续签到 N 天：取当月与上月 bitmap 拼接后按 bit 区间统计（应用层合并计算）。
**额外福利**：`BITFIELD` 支持取任意区间的无符号整数，一次拿回整月签到位做日历渲染。

内存账：100 万用户 × 12 月 × ~4 字节 ≈ 50MB 级——比"每人一行签到记录"轻两个量级。

## 三、UV 统计（HyperLogLog）

```java
redis.opsForHyperLogLog().add("uv:index:20261104", userId);
Long uv = redis.opsForHyperLogLog().size("uv:index:20261104");    // 误差 0.81%
Long monthUv = redis.opsForHyperLogLog().size("uv:20261104", "uv:20261103", ...);  // 合并月UV
```

**和 Set 的选型分界**：UV 是"数有多少不同人"（计数）→ HLL；"某用户来过没有"（判断）→ Set/Bitmap。电商大促大盘 UV 用 HLL，风控"该设备是否出现过的名单"用 Set。

## 四、组合案例：游戏活动的完整数据面

| 需求 | 方案 |
|------|------|
| 积分排行榜 | ZSet（按月分 key，留前 1w） |
| 每日签到 | Bitmap（key=用户+月） |
| 活动参与人数 | Set SCARD（需要精确/判重）或 HLL（只要数量） |
| 道具库存 | String INCR / Lua（stage4/01） |
| 中奖名单 | Set SPOP 不放回抽奖 |

一套 Redis 五种类型搞定整个活动——**按业务形状选类型**（stage1/03）的红利。

## 面试问法

**Q: 亿级用户的签到/UV 怎么设计？**
A: 签到用 Bitmap（1 人 1 月 1 key，每人每天 1 bit，BITCOUNT 出勤，亿级 ~百 MB）；UV 用 HyperLogLog（固定 12KB，0.81% 误差，PFMERGE 合并月榜）。要"用户是否来过"的精确判断则 Bitmap/Set，只要数量 HLL。排行榜 ZSet 按 period 分 key 防大 Key，ZREMRANGEBYRANK 控制榜单长度。
