## 贯穿本阶段的方法论

每个场景都按同一个推导链走（这就是"会类型"到"会设计"的距离）：

```
1. 业务需求拆细（产品功能点 → 数据操作形状）
2. 选类型（形状匹配：计数/对象/排序/去重/...）
3. 设计 key（业务:对象:ID + 分片/分period防大Key）
4. 想并发（复合操作→Lua；多实例→防重复）
5. 想可靠（Redis 丢了会怎样？要不要落 DB、怎么落）
6. 想增长（集合上限、分period、淘汰）
```
