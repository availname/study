# 01 · Redis 是什么，为什么快

> 🎬 **配套交互演示（容易看懂版）**：[diagrams/redis-fast.html](../../diagrams/redis-fast.html)——超级服务员餐厅：切换 BIO/Redis 两种经营模式，看"一个服务员怎么干过十个"。

## 一句话定位

**Redis（Remote Dictionary Server）= 一个放在内存里的超大 HashMap**，但它支持多种数据结构、可持久化到磁盘、能主从复制，所以既是**缓存**，也能当**数据库**和**消息中间件**。

在系统里的典型位置：

```
用户请求 → [应用] → ①先查 Redis 缓存（~0.5ms）
                      │ 命中 → 直接返回
                      │ 未命中 → ②查 MySQL（~50ms）→ ③回写 Redis → 返回
```

把 80% 的读请求挡在 Redis 层，数据库压力降一个数量级——这是它最普遍的用途。

## 为什么快（面试必考，四层原因）

### 1. 纯内存操作

内存随机访问 ~100ns，磁盘 ~10ms，差 **10 万倍**。Redis 的数据全部在内存里，这是"快"的根本前提。

### 2. 单线程命令执行（无锁竞争）

处理命令的核心线程只有一个——**不需要多线程锁、没有上下文切换**，不存在死锁问题，代码路径简单到极致。

> 注意精确表述：Redis 6.0+ 是"**命令执行单线程 + 网络 IO 多线程**"。数据读写、Lua、过期删除仍是单线程，但读写网络数据的解析回写可开多个 IO 线程（默认关闭）。面试答"命令执行是单线程的"。

### 3. IO 多路复用（epoll）

单线程怎么同时服务几千个连接？靠 epoll：

```
        ┌─ 连接1 可读 → 处理
epoll_wait ─ 连接3 可写 → 回复      一个线程监听所有 socket，谁就绪处理谁
        └─ 连接7 可读 → 处理
```

（对比：BIO 模型一个连接一个线程，1000 连接 = 1000 线程，光上下文切换就拖死。）Nginx、Netty 同款思路。

### 4. 高效的数据结构

值不是"傻存"，按类型选了精心设计的结构：SDS 动态字符串、跳表、压缩列表……（stage2/02 详解）。比如 `ZSCORE` 在跳表里是 O(logN)，百万元素也是毫秒内。

**答题主干背这四条**：内存 + 单线程命令执行（无锁无切换）+ IO 多路复用（epoll）+ 高效数据结构。

## Redis 能干什么（真实用途地图）

| 用途 | 数据结构 | 一句话 |
|------|---------|--------|
| **缓存** | String/Hash | 挡在 DB 前面，最主流用法 |
| 分布式锁 | String (SETNX) | 多实例互斥（stage3/03 专章） |
| 验证码/Token/Session | String + TTL | 短生命周期数据 |
| 排行榜 | ZSet | 实时排名 O(logN) |
| 抽奖/去重 | Set | 随机弹出 / 交集并集 |
| 签到打卡 | Bitmap | 1 亿人签到只占 ~12MB |
| UV 统计 | HyperLogLog | 0.81% 误差换 12KB 固定内存 |
| 附近的人 | GEO | 经纬度 + 范围查询 |
| 简单队列/延迟队列 | List / Stream | 轻量 MQ 替代（stage4/03） |
| 计数器/限流 | String INCR | 原子自增天然防并发 |

## 什么时候不该用 Redis

- 数据要强一致、绝不能丢 → 放 DB，Redis 只做加速
- 冷数据（一年访问几次）→ 别占内存，内存比磁盘贵 100 倍
- 复杂关联查询（多表 join）→ 那是 SQL 的主场
- 数据量远超内存预算 → 选磁盘型存储

## 名词速查

| 名词 | 解释 |
|------|------|
| Key/Value | 键值对；Key 是字符串，Value 按类型组织 |
| TTL | 存活时间（秒），到点删除——验证码、Token 靠它 |
| 持久化 | 内存数据落盘（RDB 快照 / AOF 日志，stage2/03） |
| 主从复制 | 一主多从，读写分离 + 数据冗余（stage2/05） |
| 哨兵 Sentinel | 自动监听主节点，挂了自动选新主 |
| 集群 Cluster | 数据分片到多节点，水平扩容 |
