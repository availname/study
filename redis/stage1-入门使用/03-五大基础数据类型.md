# 03 · 五大基础数据类型：每个类型对应一类业务

记住方法论：**不要把 Redis 当"只存字符串的缓存"，按业务形状选类型**——选对类型，逻辑复杂度直接减半。每个类型 = 一个真实业务场景。

## 1. String：最万能的默认选项

值可以是字符串、数字（能 INCR）、序列化 JSON。

```bash
# 验证码（TTL 到点自动删除）
SET captcha:login:13800001111 8848 EX 300
GET captcha:login:13800001111

# 计数器：原子自增，天然防并发（多线程同时 INCR 也不会少加）
SET article:read:1001 0
INCR article:read:1001      # → 1
INCRBY article:read:1001 50 # → 51

# 分布式锁（stage3/03 专章）
SET lock:stock:sku1 clientId NX EX 10    # NX=不存在才写(抢锁) EX=10秒自动释放

# 对象缓存（小对象 JSON 可以；字段要单独读写的用 Hash）
SET user:1001 '{"name":"张三","age":20}' EX 3600
```

| 命令 | 用途 | 注意 |
|------|------|------|
| `SET key val EX s NX` | 写+过期+不存在才写，**一条命令三件事** | 分布式锁/防重全靠它 |
| `INCR/INCRBY/DECR` | 原子计数 | 限流、阅读量、库存 |
| `SETNX` | 不存在才写 | 老写法，等价于 `SET ... NX` |
| `MSET/MGET` | 批量读写 | 减少 RTT（100 次命令 → 1 次） |

## 2. Hash：对象的部分字段读写

购物车：一个 Hash = 一个用户的购物车，field=商品ID，value=数量。

```bash
HSET cart:1001 sku1 2      # 用户1001 的购物车：sku1 买 2 件
HSET cart:1001 sku2 1
HGET cart:1001 sku1        # 读单个商品 → "2"
HINCRBY cart:1001 sku1 1   # sku1 数量 +1 → 3（原子）
HGETALL cart:1001          # 整个购物车 → sku1=3, sku2=1
HDEL cart:1001 sku2        # 删一个商品
HLEN cart:1001             # 几种商品
```

**String 存 JSON vs Hash 怎么选**：
- 整体读写（渲染页面）→ String JSON，一次 GET
- **高频改单个字段**（购物车加减、对象某属性）→ Hash，不用"读-改-写全量 JSON"
- 字段数上百的大对象 → Hash 注意大 Key（stage3/04）

## 3. List：有序、可两端操作 → 最新列表 / 简单队列

```bash
# 最新消息列表（朋友圈动态，只留最近 100 条）
LPUSH feed:1001 "动态3" "动态2" "动态1"   # 左插（新的在左）
LRANGE feed:1001 0 9                      # 前 10 条（分页）
LLEN feed:1001
LTRIM feed:1001 0 99                      # 只留 100 条，防大 Key

# 简单队列：生产者 LPUSH，消费者 BRPOP（阻塞式右弹）
LPUSH order:queue "订单1"
BRPOP order:queue 5                       # 5 秒没消息阻塞等待，避免轮询
```

| 场景 | 用法 |
|------|------|
| 最新动态/评论前 N 条 | LPUSH + LTRIM |
| 轻量任务队列 | LPUSH + BRPOP |
| 时间线 | LPUSH + LRANGE 分页 |

> 注意：List 分页是按位置（下标会随 LPUSH 移动），**深度分页/稳定分页用 ZSet 或 DB**。

## 4. Set：无序不重复 → 抽奖 / 标签 / 共同好友

```bash
# 抽奖池：报名去重
SADD lottery:2026 u1 u2 u3 u4
SISMEMBER lottery:2026 u1     # 报过名吗 → 1（防重复报名）
SCARD lottery:2026            # 多少人参加
SRANDMEMBER lottery:2026 2    # 随机抽 2 人（不放回）
SPOP lottery:2026             # 抽中即移除（不放回抽奖）

# 共同好友：交集
SADD friends:u1 u2 u3 u5
SADD friends:u2 u3 u5 u9
SINTER friends:u1 friends:u2  # → u3 u5（共同好友）
SUNION / SDIFF                # 并集 / 差集(我关注他他没关注我)
```

Set 的交并集是**服务端计算**，数据量大时是 O(N) 操作——百万级成员的 SINTER 会阻塞，考虑 SINTERSTORE 到后台算或拆分。

## 5. ZSet：带分数的排序集合 → 一切排行榜

```bash
# 游戏排行榜：member=玩家，score=分数
ZADD rank:game 3200 玩家A 2800 玩家B 3500 玩家C
ZINCRBY rank:game 100 玩家B               # B 加 100 分 → 2900（原子）
ZREVRANGE rank:game 0 2 WITHSCORES        # 前 3 名（降序）+ 分数
ZREVRANK rank:game 玩家B                  # B 的名次（0 开始）→ 2
ZSCORE rank:game 玩家A                    # 查分数
ZRANGEBYSCORE rank:game 3000 +inf         # 3000 分以上的玩家（筛选）
ZCARD rank:game                           # 参赛总人数
ZREMRANGEBYRANK rank:game 0 9             # 踢出榜尾 10 名（防大 Key）
```

| 场景 | score 放什么 |
|------|-------------|
| 游戏排行 | 积分 |
| 热搜榜 | 热度值（浏览×权重 + 时间衰减因子） |
| 延迟队列 | 到期时间戳（stage4/03） |
| 滑动窗口限流 | 请求时间戳 |

## 选型速查表（背下来）

| 业务形状 | 类型 |
|---------|------|
| 单值 / 计数 / 锁 | String |
| 对象 + 按字段读写 | Hash |
| 最新 N 条 / 简单队列 | List |
| 去重 / 交并集 / 随机 | Set |
| 排序 / 排名 / 范围 | ZSet |

## 面试问法

**Q: Redis 有哪些数据类型，分别什么场景？**
A: 五基础 + 三特殊。String：缓存、计数器、分布式锁；Hash：对象字段级读写（购物车）；List：最新列表、轻量队列（BRPOP 阻塞弹）；Set：去重、抽奖、共同好友（交并集）；ZSet：排行榜、延迟队列（score 排序）。特殊类型：Bitmap 签到、HyperLogLog 亿级 UV、GEO 附近的人（stage1/04）。核心思想是按业务形状选类型。
