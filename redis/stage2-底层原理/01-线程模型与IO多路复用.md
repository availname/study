# 01 · 单线程模型与 IO 多路复用

Stage 1 说过 Redis 快的四层原因，本章把"单线程 + IO 多路复用"拆透。这是 Redis 面试的第一道门。

## 单线程到底指什么

**精确表述**：Redis 的**命令执行**是单线程（读写数据、执行 Lua、过期清理），但辅助工作是多线程的——6.0 起网络 IO 可多线程、后台线程负责异步删除（UNLINK）、AOF 刷盘、关闭文件等。

```
客户端1 ─┐
客户端2 ─┼→ [IO 线程(可选)] 解析请求 → 【单线程 命令执行队列】 → 回写响应
客户端N ─┘      (6.0 可选)         无锁，顺序执行
```

**为什么单线程反而快**：

| 多线程程序的成本 | Redis 单线程 |
|----------------|-------------|
| 锁竞争（读写锁/分布式并发控制） | 无锁，天然串行安全 |
| 上下文切换（~µs 级，cache 失效） | 零切换 |
| 线程安全设计复杂度（ConcurrentHashMap 的复杂度） | 所有命令原子，业务不用防并发 |

前提是：**每个命令都快**（内存操作）。所以单线程成立；反过来这也解释了 stage1/04 的警告——`KEYS *` 这种慢命令会卡住**所有**客户端（单线程被堵，全端排队）。

## IO 多路复用：一个线程看住一万个连接

### 先看反例：BIO（阻塞 IO）

```java
// 传统写法：一个连接一个线程
while (true) {
    Socket client = server.accept();          // 阻塞等连接
    new Thread(() -> handle(client)).start(); // 每个连接一个线程
}
// 1 万连接 = 1 万线程 ≈ 数 GB 内存 + 海量上下文切换 → 崩
```

### Redis 的做法：epoll（事件驱动）

```
            ┌── fd=3 就绪(可读) ──┐
epoll_wait  ─┼── fd=7 就绪(可读)  ─┼──→ 单线程依次处理就绪的事件
            └── fd=12 就绪(可写) ──┘
（没就绪的连接不占 CPU，只是 epoll 里的一个登记项）
```

- **select/poll**：每次把全部连接集合传给内核，内核线性扫描 → O(N)，连接多就慢
- **epoll**：内核维护红黑树登记连接，就绪的放入就绪链表，应用只处理就绪的 → O(1) 事件驱动
- Redis 用 epoll（Linux）/ kqueue（BSD）/ IOCP（Windows），封装在事件循环 `ae` 库里

主循环伪代码：

```c
while (true) {
    events = aePoll(wait);          // 等 epoll 通知（有超时，兼顾定时任务）
    for (e in events) {
        if (e 是读) 处理命令();       // 命令执行——单线程
        if (e 是写) 回写响应();
    }
    执行定时任务();                   // 过期删除、AOF 刷盘检查等（每 100ms 级）
}
```

**Netty/Nginx/Redis 同源思想**：事件驱动 + 多路复用 + 少量线程。学透一个，三个都通。

## 6.0 的多线程 IO

单线程的瓶颈出现在**网络 IO**（解析协议、拷贝数据、回写响应）——内存命令太快，IO 跟不上时 CPU 单核打满。Redis 6.0 开启 `io-threads 4` 后：

- IO 线程组负责**读解析 + 写回**（并行）
- **命令执行仍是单线程**（数据一致性不变）

默认关闭。经验：QPS 10 万以下不用开；大流量、大 value 场景收益明显。

## 单线程带来的三条纪律（贯穿 stage3）

1. **禁用慢命令**：`KEYS *`、`FLUSHALL`、未分页的 `SMEMBERS`/`HGETALL` 大集合——一条命令卡住全端。用 SCAN/分页/UNLINK 替代。
2. **大 Key 是毒药**：读写 10MB 的 value = 单线程被占用十几毫秒，QPS 直接腰斩（stage3/04）。
3. **不用 Redis 做重计算**：百万级 SINTER 是 O(N)——计算下沉应用或后台任务。

> 排查工具：`SLOWLOG GET`（慢查询日志）、`redis-cli --latency`（延迟探测）、`INFO commandstats`（各命令耗时统计）。

## 面试问法

**Q: Redis 为什么单线程还这么快？**
A: 四层：纯内存；命令执行单线程无锁无切换；epoll 多路复用一个线程处理海量连接；数据结构高效。补充：6.0 网络 IO 可多线程但命令执行仍单线程；单线程的代价是慢命令会阻塞全端，所以生产要防大 Key、禁 KEYS。

**Q: 单线程的 Redis 怎么利用多核？**
A: 一条路是部署多实例（集群分片，每实例一个核，stage2/05）；一条是 6.0 的 io-threads 让网络 IO 并行但命令执行保持单线程。
