# 05 · RAG 进阶：基础版之后的六种升级

基础 RAG（切分→向量化→Top-K→生成）在真实业务里命中率往往不够。本篇讲六种进阶技术，**按投入产出比排序**——前三个是"必做"，后三个按需。

## 快速回顾：基础 RAG 的三个薄弱点

| 薄弱点 | 表现 |
|--------|------|
| **检索不准** | 用户问法与文档用词不一致 → 向量相似度低 → 检索不到 |
| **块不完整** | 答案跨两个块，或块太大淹没重点 |
| **生成跑偏** | 检索到了但 LLM 没用好，或检索了一堆噪声 |

六种升级逐一对症：

## 升级 1：查询改写（Query Rewriting）★ 必做

用户的原始问题往往不适合直接检索（口语化/带历史上下文/多问混合）。**用 LLM 先改写查询**：

```
用户原始问题（带历史）：
  "那第二种方案呢？"          ← 脱离上下文无法检索

改写后（LLM 一次调用）：
  "事务隔离级别 RR 的优缺点是什么？"   ← 补全指代，独立可检索
```

变体技术：

| 技术 | 做法 | 适用 |
|------|------|------|
| **HyDE** | 让 LLM 先"假想答案"，用假答案的向量去检索（答案与文档更相似） | 零成本提升召回 |
| **多查询 Multi-Query** | 一个问题改写成 3 个不同角度 → 分别检索 → 合并去重 | 覆盖多角度 |
| **查询分解** | 复合问题拆成多个子问题分别检索 | "对比 A 和 B 并给出选型" → 3 个子查询 |

**成本提示**：每次改写多一次 LLM 调用——查询改写用**小模型/低 token**，性价比最高。

## 升级 2：混合检索（Hybrid Search）★ 必做

纯向量检索的盲区：**专有名词/编号/代码**的语义向量不明显（"ERR-1042 是什么错误"和文档里"ERR-1042"语义距离可能很远）。

```
混合检索 = 向量检索（语义） + 关键词检索（BM25，精确匹配）
            ↓ RRF（Reciprocal Rank Fusion，倒数排名融合）合并两路结果
```

- 向量路：找"意思相近"的
- 关键词路：找"字面匹配"的（专有名词/型号/报错码）
- 两路合并取并集，排名融合——**互补盲区**

RediSearch 原生支持混合（KNN + TEXT 联合查询）；Elasticsearch 天然支持。

## 升级 3：重排序（Rerank）★ 强烈推荐

向量检索的 Top-K 是"粗召回"（快但排序粗）。**两阶段检索**：

```
① 向量粗召回：Top-50（快，毫秒级）
② Rerank 精排：Cross-Encoder 模型对"问题×每个候选"逐一精算相关度 → 取 Top-3
```

Cross-Encoder（如 bge-reranker、Cohere Rerank）比 Bi-Encoder 精确得多——**最终进提示词的 3 块质量显著提升**。代价：50 次精算（仍毫秒~几十毫秒级，可接受）。

```
粗召回（便宜、快、召回率高）→ 精排（贵、准、只排头部）——与秒杀漏斗同哲学：漏斗每层过滤
```

## 升级 4：父子分块（Small-to-Big）

检索用**小块**（精准命中），返回给 LLM 用**父块**（完整上下文）：

```
父块 = 整个章节（1000 字，进提示词）
子块 = 章节内的段落（200 字，用于检索）
命中子块 → 返回它的父块（上下文完整）
```

解决"切小块丢了上下文 vs 切大块检索不准"的两难。

## 升级 5：GraphRAG（知识图谱增强）

把文档抽取成**实体-关系图谱**（"Spring 事务 --失效场景--> 自调用"），检索时图谱遍历 + 向量检索结合。适合：关系密集的领域（法规条文/系统架构文档）。代价：抽取与维护成本高——** 大规模文档 + 多跳推理问题才值得**。

## 升级 6：Agentic RAG（智能体自主检索）

不再固定"检索→生成"流程，而是让 **Agent 自主决定**：要不要检索？检索什么？检索结果够不够？不够就再检索（下一章 AI Workflow 详述）。适合复杂多步问题。

## 效果评估：RAG 优化必须有度量

| 指标 | 测什么 | 工具 |
|------|--------|------|
| 检索命中率 | Top-K 里是否含正确块 | 标注 20~50 个问答对跑评测 |
| 答案忠实度 | 回答是否忠于检索资料（防幻觉） | LLM as judge（用强模型评弱模型） |
| 端到端正确率 | 最终答案与标注答案对比 | 评测集回归 |

**没有评测集的 RAG 调优 = 玄学**。先建 20~50 条评测集，再动手优化——每次改动跑一遍对比。

## 面试问法

**Q: 你的 RAG 效果不好，怎么优化？**
A: 按漏斗逐层排查——①检索层：查询改写（HyDE/多查询）+ 混合检索（向量+BM25，互补专有名词盲区）+ 重排序（Cross-Encoder 精排 Top-K）；②数据层：分块策略（父子分块 small-to-big 兼顾精准与上下文）；③生成层：提示词限定"只依据资料回答"+ 允许说不知道；④**必须先建评测集**（命中率/忠实度/端到端正确率），没有度量的一切调优都是玄学。复杂多跳问题上 Agentic RAG（Agent 自主决定检索策略）。
